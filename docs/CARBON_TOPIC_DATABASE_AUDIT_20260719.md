核查日期：2026-07-19

## 现库结构与数据量

- `carbon_emission_factor`：6 行；主键 `id`，唯一键 `factor_code`，`data_nature` 普通索引。具备因子版本、演示性质、核验状态和可空 `evidence_document_id`，但没有 `is_demo`、证据状态及实际外键。
- `carbon_emission_activity`：6 行（2026-02 至 2026-07）；主键 `id`，仅 `period_value` 普通索引。具备活动量、四类排放、基准排放、因子 ID、演示性质和核验状态，但没有稳定业务编码、边界、单位、证据状态、`is_demo`；因子列没有外键。
- `carbon_material_usage`：18 行（三种材料 × 六个月）；主键 `id`，仅 `period_value` 普通索引。具备活动/因子 ID、排放量和演示状态，但没有证据状态、`is_demo`，关联列没有外键。
- 未发现碳排基准、减排核算、低碳措施、措施成本、措施月效或碳核算证据关联表。
- E04 历史迁移 `server/migrations/20260718_e04_demo_accounting_v0_1.py` 已落实 6 个因子、6 条月度活动、18 条材料明细；源合计、材料合计和月度累计均为 12,856 / 2,486 / 12,856。

## 当前数据链与回退顺序

`DashboardPage.vue` 点击 CARBON → `getDashboardTopic('carbon')` → `GET /api/dashboard/topics/carbon` → `mysql_api.get_carbon_topic_detail()` → MySQL 活动表动态聚合，并把数据库结果覆盖到 `dashboard_topic_snapshot` 的 JSON 基底。请求失败或返回空时，前端回退 `dashboard.mock.ts`；专题内部单个数据块缺失时，`KpiDetailModal.vue` 又逐块回退 `carbonTabData`。

因此当前顺序名义上是 MySQL → 服务端快照 → 前端 Mock，但服务端接口的部分区块（措施、成本、标签、静态说明）仍直接继承快照，且响应只返回 `isMock:false`，没有逐块来源说明，也没有 `sourceMode`。

## 冲突数据结论

### 1,445 与 2,840 tCO₂e

- 1,445 tCO₂e 有数据库链：六个月基准排放合计 14,301，实际排放合计 12,856，按 `14,301 - 12,856 = 1,445` 得出。月份存在，但没有独立核算 ID、独立边界编码、证据状态或外键化基准方案。
- 2,840 tCO₂e 在当前仓库源码、JSON 快照及 MySQL 碳相关表中均无记录，无法证明口径、月份或稳定 ID，不得入库或与 1,445 合并。
- 当前四项快照措施效果为 320、280、150、200 tCO₂e，合计 950 tCO₂e，属于无稳定 ID、无核验状态的前端展示性“预计减排”，与 1,445 没有可证明的核算关系。

### 成本数据

- 320 万元投入、85 万元运行节约、120 万元避免成本：来自服务端 `dashboard_payload.json` 快照，并有同值前端 Mock；数据库无记录。
- 成本影响 0：`mysql_api.get_carbon_topic_detail()` 与面板聚合函数硬编码，不是三项成本的计算结果。
- 3.2 万元：在本专题源码、快照和数据库中未找到；如首页截图存在该数值，应视为另一未知口径，不能覆盖或并入专题成本。
- 只有在三项属于同一范围与期间时，演示净成本影响才可按 `320 - 85 - 120 = 115 万元` 展示，并必须标注“演示测算，非财务确认结果”。

## 推荐最小数据库增量

1. `carbon_emission_baseline`：稳定基准编码、核算期间、边界、排放、单位、因子版本及演示/核验/证据状态。
2. `carbon_reduction_accounting`：逐月关联基准，存同边界同单位的基准、实际和核算差额，并用数据库约束或迁移校验公式。
3. `carbon_reduction_measure`：稳定措施编码；分列预计减排、核验减排、投入、运行节约、避免成本、净成本影响。
4. `carbon_measure_monthly_performance`：跨月措施成效与成本明细。
5. `carbon_accounting_evidence_link`：只关联既有 `document_id`，不复制资料文件。

所有演示记录使用 `data_nature='demo'`、`is_demo=1`、`verification_status='待业务核验'`、`evidence_status='未关联'` 和稳定编码。迁移采用唯一键与 upsert 保证幂等，不删除、不覆盖非演示记录。
