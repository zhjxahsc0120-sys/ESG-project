# 月报准备与输出｜前端接口交接

## 1. 最终接口

- 主接口：`GET /api/monthly/report-overview?reportMonth=2026-07`
- 同契约别名：`GET /api/monthly/readiness?reportMonth=2026-07`
- 首页旧专题兼容接口：`GET /api/dashboard/topics/monthly-report`
- 完整响应示例：[monthly_report_overview.example.json](./monthly_report_overview.example.json)

主接口以 `reportMonth` 查询月份，当前有数据月份为 `2026-07`。响应由服务端聚合，HTTP 200；找不到月份时返回404。新版页面应优先使用主接口，不应再读取前端Mock或旧的六章节/六缺项结构。

## 2. 冻结口径

- 资料归集率：82%（精确值81.8%，展示值由后端给出）
- 已归集：18/22项
- 待提交1、待确认1、待补正2、待处理合计4、不适用0
- 固定月度16、条件触发4、周期引用2
- 截止日期：2026-08-02至2026-08-05
- 校验：`22 = 18 + 1 + 1 + 2 + 0`
- E/S/G：88%（7/8）、100%（5/5）、67%（6/9），均从22项任务事实聚合

## 4. 枚举与旧状态映射

任务类型：`MONTHLY_FIXED=固定月度`、`CONDITIONAL=条件触发`、`PERIODIC_REFERENCE=周期引用`。

流程节点状态：`IN_PROGRESS=进行中`、`PENDING=待完成`、`NOT_STARTED=未开始`、`COMPLETED=已完成`。

服务端已统一旧状态，前端不得二次猜测：

| 旧值 | 新值 |
|---|---|
| 待补齐、待补件 | 待补正 |
| 待审核 | 待确认 |
| 已完成 | 校验通过 |
| 编制中 | 待提交 |
| 不适用（已确认） | 不适用 |

## 7. 人员、空值和展示规则

允许的责任角色：环保资料专员、水保资料专员、安全资料专员、劳务管理专员、合规资料专员、监理资料专员、ESG月报管理员、部门审核负责人。

- 人员展示优先级：`responsibleUserName`非空时显示姓名；否则显示`responsibleRole`；再为空才显示`—`。
- 当前无正式人员主数据，22项的`responsibleUserId`和`responsibleUserName`均为`null`，不得生成姓名。
- 数量0必须显示0，不能当作空值隐藏。
- 日期为空显示`—`，不得推断日期。
- `linkedDocumentIds=[]`表示尚无人工确认的资料证据，不得把AI匹配结果直接当作正式关联。
- `outputId/version=null`且`outputStatus.status=NOT_CREATED`表示没有真实输出记录；不得伪造PDF、版本号或审核结果。

## 8. 来源字段

- `sourceMode=mysql`：本次响应来自MySQL事实表。
- `sourceMode=server-json`：MySQL不可用时使用同一字段契约的服务端JSON快照回退。
- `sourceMode=frontend-mock`：仅前端最后兜底；不得覆盖有效MySQL结果。
- `isMock=false`：响应不是Mock。前端不得仅凭`dataNature=demo`把它改判为Mock。
- `dataNature=demo`：当前22项是明确标识的演示任务实例；正式/演示混合时为`mixed`，全正式时为`formal`。

## 9. 尚未接入的数据

- 正式资料人工关联：演示资料要求已建链，但`linkedDocumentIds`目前为空；AI_MATCH不计入正式关联。
